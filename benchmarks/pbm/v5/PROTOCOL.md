# PBM v5 platform-outcome protocol

PBM v5 compares Codex Desktop with Codex Room as platforms.

The benchmark fixes the starting state, mission, success criteria, grading, intervention rules, and measurement boundaries. It does **not** prescribe either platform's internal workflow.

## Shared measured contract

Both platforms receive the same frozen seven-task battery and equivalent starting files.

Both must ultimately satisfy the task-specific requirements and create the required completion marker.

After measured work begins, the principal supplies no substantive guidance.

Each platform may use its native capabilities however it chooses: sequential work, parallel work, delegation, subagents, peer coordination, or no delegation at all. PBM does not prescribe the number, identity, sequencing, working directories, or implementation mechanics of internal agents.

## Desktop boundary

The measured Desktop execution is one fresh top-level native Codex task rooted at the prepared Desktop battery workspace.

The principal gives that task exactly:

`Read BENCHMARK.md and execute it exactly. Do not ask me questions. When complete, stop.`

PBM automatically discovers that top-level rollout from the prepared workspace. Any native descendant tasks created by Desktop are part of Desktop's platform execution. Their provider usage is included in Desktop's aggregate measurement. PBM does not direct or message those descendants.

## Room boundary

The measured Room is one fresh ordinary Codex Room with the same battery workspace and mission. Normal Room cognition and A/B/C coordination remain available. PBM does not prescribe which peers C invokes or how the Room sequences the work.

## Result boundary

PBM evaluates:
- final workspace correctness with the frozen task graders;
- required completion marker;
- absence of substantive principal intervention after launch;
- complete provider usage evidence;
- total platform token usage;
- elapsed measured duration;
- provenance sufficient to bind the execution to the prepared workspace and run.

Internal orchestration is evidence and cost, not a validity requirement except where it shows principal intervention or escapes the prepared benchmark boundary.
